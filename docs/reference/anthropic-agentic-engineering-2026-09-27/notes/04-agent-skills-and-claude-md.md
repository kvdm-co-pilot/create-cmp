# Agent Skills, SKILL.md authoring, and CLAUDE.md / rules / auto-memory best practices (state as of 2026-09-27)

Scope note: all findings below were fetched 2026-09-27 from primary sources (agentskills.io, code.claude.com/docs, platform.claude.com/docs, anthropic.com / claude.com blogs, github.com/anthropics/*). Where a page carries no date, the date given is the fetch date and the Claude Code version the docs reflect (CHANGELOG top entry 2.1.283 on 2026-09-27). Superseded guidance and 2026 changes are flagged inline.

## Q1. The Agent Skills spec: frontmatter, limits, layout, adopters, and what changed since Oct 2025

### Takeaway
The spec (agentskills.io/specification) defines a skill as a directory with a required `SKILL.md` (YAML frontmatter + Markdown body) and optional `scripts/`, `references/`, `assets/`; six frontmatter fields exist (`name`, `description` required; `license`, `compatibility`, `metadata`, `allowed-tools` optional), with hard limits of 64 chars (name) / 1024 chars (description) / 500 chars (compatibility). Launched 2025-10-16 as a Claude feature, opened as a vendor-neutral standard 2025-12-18, and by mid/late 2026 ~40+ agents (Codex, Copilot, VS Code, Cursor, Gemini CLI, Goose, OpenCode, Kiro, Databricks, Snowflake, Spring AI, ...) list themselves as compatible.

### Cited Findings
- Directory structure: `skill-name/` containing `SKILL.md` (required: metadata + instructions), `scripts/` (optional executable code), `references/` (optional documentation), `assets/` (optional templates/resources), "Any additional files or directories" — [Agent Skills Specification](https://agentskills.io/specification)
- Frontmatter table (verbatim constraints): `name` — Yes — "Max 64 characters. Lowercase letters, numbers, and hyphens only. Must not start or end with a hyphen."; `description` — Yes — "Max 1024 characters. Non-empty. Describes what the skill does and when to use it."; `license` — No; `compatibility` — No — "Max 500 characters. Indicates environment requirements (intended product, system packages, network access, etc.)"; `metadata` — No — "Arbitrary key-value mapping ... (a map from string keys to string values)"; `allowed-tools` — No — "Space-separated string of pre-approved tools the skill may use. (Experimental)" — [Agent Skills Specification](https://agentskills.io/specification)
- `name` additional rules: "Must not contain consecutive hyphens (`--`)" and "Must match the parent directory name" — [Agent Skills Specification](https://agentskills.io/specification)
- `description`: "Should describe both what the skill does and when to use it" and "Should include specific keywords that help agents identify relevant tasks"; poor example given is `description: Helps with PDFs.` — [Agent Skills Specification](https://agentskills.io/specification)
- `compatibility`: "Should only be included if your skill has specific environment requirements"; note: "Most skills do not need the `compatibility` field." Example: `compatibility: Requires git, docker, jq, and access to the internet` — [Agent Skills Specification](https://agentskills.io/specification)
- `allowed-tools` example: `allowed-tools: Bash(git:*) Bash(jq:*) Read`; "Support for this field may vary between agent implementations" — [Agent Skills Specification](https://agentskills.io/specification)
- Body: "There are no format restrictions." Recommended sections: step-by-step instructions, examples of inputs and outputs, common edge cases. "the agent will load this entire file once it's decided to activate a skill. Consider splitting longer `SKILL.md` content into referenced files." — [Agent Skills Specification](https://agentskills.io/specification)
- Progressive disclosure budget in the spec: "1. **Metadata** (~100 tokens): The `name` and `description` fields are loaded at startup for all skills 2. **Instructions** (< 5000 tokens recommended): The full `SKILL.md` body is loaded when the skill is activated 3. **Resources** (as needed)". "Keep your main `SKILL.md` under 500 lines." — [Agent Skills Specification](https://agentskills.io/specification)
- File references: "use relative paths from the skill root"; "Keep file references one level deep from `SKILL.md`. Avoid deeply nested reference chains." — [Agent Skills Specification](https://agentskills.io/specification)
- `scripts/` guidance: "Be self-contained or clearly document dependencies; Include helpful error messages; Handle edge cases gracefully"; `references/`: "Keep individual reference files focused. Agents load these on demand, so smaller files mean less use of context." — [Agent Skills Specification](https://agentskills.io/specification)
- Validation tooling: `skills-ref validate ./my-skill` from the `agentskills/agentskills` repo "checks that your SKILL.md frontmatter is valid and follows all naming conventions" — [Agent Skills Specification](https://agentskills.io/specification); repo is Apache 2.0 code / CC-BY-4.0 docs, 25.7k stars, 145 commits, no CHANGELOG or numbered spec versions visible — [agentskills/agentskills on GitHub](https://github.com/agentskills/agentskills)
- Governance statement on the site: "The Agent Skills format was originally developed by Anthropic, released as an open standard, and has been adopted by a growing number of agent products. The standard is open to contributions from the broader ecosystem." — [Agent Skills Overview](https://agentskills.io/)
- Launch date of the feature: 2025-10-16, across Claude apps (Pro/Max/Team/Enterprise), Claude Code (plugin marketplace) and the Developer Platform with a new `/v1/skills` endpoint; described as "composable", "portable", "efficient" — [Introducing Agent Skills (claude.com/blog/skills)](https://claude.com/blog/skills) (anthropic.com/news/skills now 308-redirects here)
- Open-standard publication: Anthropic published the spec at agentskills.io on 2025-12-18; adopters named at that time: Microsoft, OpenAI, Atlassian, Figma, Cursor, GitHub — [SiliconANGLE 2025-12-18](https://siliconangle.com/2025/12/18/anthropic-makes-agent-skills-open-standard/); [VentureBeat](https://venturebeat.com/ai/anthropic-launches-enterprise-agent-skills-and-opens-the-standard)
- Client showcase on agentskills.io (fetched 2026-09-27) lists, among others: Claude Code, Claude, ChatGPT & Codex, GitHub Copilot, VS Code, Cursor, Gemini CLI, Junie (JetBrains), OpenCode, OpenHands, Goose, Roo Code, Kiro, Amp, Factory, Letta, Databricks Genie Code, Snowflake Cortex Code, Spring AI, Laravel Boost, Pulumi Neo, Tabnine, Mistral Vibe, Hermes Agent, OpenClaw, Qodo, TRAE — [Agent Skills Overview](https://agentskills.io/) (the page's embedded client list; each entry links to its own docs)
- Spring AI added generic Agent Skills support 2026-01-13 — [Spring AI blog](https://spring.io/blog/2026/01/13/spring-ai-generic-agent-skills/)
- Third-party ecosystem report (dated 2026-06-25) timeline: Oct 2025 launch; 2025-12-18 open standard; Jan 2026 Claude Code 2.1.0 skill hot-reloading; Feb 2026 org-wide management; ~40 compatible products by June 2026; SkillsBench: 47,150 public skills analyzed, mean quality 6.2/12, curated skills +16.2 pp pass-rate lift; Snyk "ToxicSkills": prompt injection in 36% of tested skills — [Agentman ecosystem report](https://agentman.ai/blog/agent-skills-ecosystem-report-2026) (secondary source; claims not independently verified here)
- Claude Code's own statement of its relationship to the spec: "Claude Code skills follow the Agent Skills open standard ... Claude Code extends the standard with additional features like invocation control, subagent execution, and dynamic context injection." — [Extend Claude with skills (code.claude.com)](https://code.claude.com/docs/en/skills)
- Anthropic's platform docs add two constraints beyond the spec: `name` "Cannot contain XML tags" and "Cannot contain reserved words: 'anthropic', 'claude'"; `description` "Cannot contain XML tags" — [Skill authoring best practices (platform.claude.com)](https://platform.claude.com/docs/en/agents-and-tools/agent-skills/best-practices)
- Anthropic's own skills repo: `./skills/` (examples by category), `./spec/` (the spec), `./template/`; install via `/plugin marketplace add anthropics/skills`; most skills Apache 2.0, document skills source-available; "These skills are for demonstration and educational purposes. Test thoroughly before production use." 179k stars / 21.1k forks at fetch — [anthropics/skills](https://github.com/anthropics/skills)

### Inferences
- The spec itself has no version number or changelog; "what changed" must be read from the published docs. Comparing the Oct-2025 launch material (only `name`/`description`) with the current spec, the additions are `license`, `compatibility`, `metadata` and (experimental) `allowed-tools`, the "must match parent directory name" rule, and the explicit ~100 / <5000 token budgets. Treat this as inferred from doc state, not from a dated diff.
- Only the six spec fields are portable. Everything else in a Claude Code SKILL.md (see Q2) is a Claude Code extension and will be rejected on upload to claude.ai or the Skills API.

### Gaps
- No primary Anthropic/agentskills.io source found stating that the Agentic AI Foundation stewards the Skills spec; the claim appears in a third-party report (Agentman) and VentureBeat says the Foundation was co-founded by Anthropic/OpenAI/Block. The agentskills GitHub repo mentions no foundation. Treat "AAIF stewardship" as unverified.
- No dated changelog of spec revisions exists; exact dates when `compatibility`, `metadata`, `allowed-tools` were added could not be established.

## Q2. How Claude Code discovers and loads skills; Claude Code-specific frontmatter; commands vs skills vs subagents vs MCP

### Takeaway
Claude Code loads only a listing of skill names+descriptions into context every turn (budget 1% of the context window; each entry's description+`when_to_use` capped at 1,536 chars), loads the full SKILL.md on invocation, and supports ~20 extra frontmatter fields beyond the spec (`when_to_use`, `argument-hint`, `arguments`, `disable-model-invocation`, `user-invocable`, `disallowed-tools`, `model`, `effort`, `context`, `agent`, `background`, `hooks`, `paths`, `shell`). Custom commands have been merged into skills (no hard deprecation); hooks are the deterministic layer, skills/CLAUDE.md are advisory.

### Cited Findings
- Loading model: "By default, skill descriptions load at session start so Claude can decide when to use them. Set `disable-model-invocation: true` in a skill's frontmatter to hide it from Claude entirely until you invoke it manually." Context-cost table: Skills — "Descriptions at start, full content when used" — "Low (descriptions every request)" — [Extend Claude Code (features-overview)](https://code.claude.com/docs/en/features-overview)
- Listing budget: "Claude Code loads a listing of skill names and descriptions into context ... if you have many skills, Claude Code drops some descriptions to fit the listing's character budget ... The budget scales at 1% of the model's context window. When the listing overflows, Claude Code drops descriptions starting with the skills you invoke least" — [Extend Claude with skills](https://code.claude.com/docs/en/skills)
- Per-entry cap: "Put the key use case first: the combined `description` and `when_to_use` text is truncated at 1,536 characters in the skill listing to reduce context usage." Cap is configurable via `skillListingMaxDescChars`; budget via `skillListingBudgetFraction` (e.g. `0.02`) or `SLASH_COMMAND_TOOL_CHAR_BUDGET`; low-priority skills can be set to `"name-only"` in `skillOverrides` — [Extend Claude with skills](https://code.claude.com/docs/en/skills)
- `description` is "Recommended" (not required) in Claude Code: "If omitted, uses the first non-empty line of the markdown content." `name` is optional and "Defaults to the directory name." — [Extend Claude with skills](https://code.claude.com/docs/en/skills)
- `when_to_use`: "Additional context for when Claude should invoke the skill, such as trigger phrases or example requests. Appended to `description` in the skill listing and counts toward the 1,536-character cap." Field names use hyphens "except `when_to_use`" — [Extend Claude with skills](https://code.claude.com/docs/en/skills)
- Other Claude Code fields (verbatim purposes): `disable-model-invocation` ("prevent Claude from automatically loading this skill ... Also prevents the skill from being preloaded into subagents"; since v2.1.196 also blocks scheduled-task firing); `user-invocable: false` ("hides it from the `/` menu ... Use for background knowledge users shouldn't invoke directly"); `allowed-tools` ("Tools Claude can use without asking permission during the turn that invokes this skill. The grant clears when you send your next message."); `disallowed-tools`; `model`; `effort` (`low|medium|high|xhigh|max`); `context: fork`; `agent`; `background` (v2.1.218+); `hooks` ("Hooks that Claude Code registers when the skill is invoked and keeps running for the rest of the session"); `paths` ("Claude loads the skill automatically only when working with files matching the patterns"); `shell` (`bash`|`powershell`); `metadata` ("Claude Code doesn't act on its contents"); `license` and `compatibility` ("Claude Code accepts the field but doesn't act on it"; compatibility ≤500 chars) — [Extend Claude with skills](https://code.claude.com/docs/en/skills)
- Portability rule: "Claude Code accepts every field in the table above. Outside Claude Code, you can use only the fields in the Agent Skills spec" — [Extend Claude with skills](https://code.claude.com/docs/en/skills)
- Sanitization (v2.1.228+): Claude Code "removes control characters, and in text that reaches Claude, such as the description, it also escapes angle brackets so the text can't imitate Claude Code's internal formatting" — [Extend Claude with skills](https://code.claude.com/docs/en/skills)
- Where skills live / precedence: enterprise (managed) > personal `~/.claude/skills/` > project `.claude/skills/` > nested `<subdir>/.claude/skills/` (loads when working on files there; clash shows as `<dir>:<name>`) > plugin `<plugin>/skills/` (namespaced `/plugin:skill`, or `/skill` if unique) > `--add-dir` > claude.ai synced skills (`~/.claude/skills/synced/`, v2.1.273+) > bundled — [Extend Claude with skills](https://code.claude.com/docs/en/skills); nested-skills behavior also in CHANGELOG: "Skills in nested `.claude/skills` directories now load when working on files there; on a name clash, the nested skill appears as `<dir>:<name>`" — [Claude Code CHANGELOG](https://github.com/anthropics/claude-code/blob/main/CHANGELOG.md)
- Hot reload: Claude Code watches skill directories and reloads changed skills within a session; CHANGELOG: "Fixed skill hot-reload re-sending the entire skill listing when a single skill changed; only changed skills are now re-announced" — [Claude Code CHANGELOG](https://github.com/anthropics/claude-code/blob/main/CHANGELOG.md)
- Commands merged into skills: "**Custom commands have been merged into skills.** A file at `.claude/commands/deploy.md` and a skill at `.claude/skills/deploy/SKILL.md` both create `/deploy` and work the same way. Your existing `.claude/commands/` files keep working. Skills add optional features: a directory for supporting files, frontmatter to control whether you or Claude invokes them, and the ability for Claude to load them automatically when relevant." — [Extend Claude with skills](https://code.claude.com/docs/en/skills)
- In plugins: "Commands are the older format, and skills supersede them for new work. A skill runs by name the same way, and it can also carry supporting files in its directory. Keep `commands/` for files you're moving over from `.claude/commands/`." `commands/<file>.md` becomes `/<plugin>:<file>` — [Plugin components](https://code.claude.com/docs/en/plugins/components)
- Skills vs subagents: "**Skills** are reusable content you can load into any context; **Subagents** are isolated workers that run separately"; "Skills can be reference or action"; "They can combine. A subagent can preload specific skills (`skills:` field). A skill can run in isolated context using `context: fork`." In subagents, "skills listed in the subagent's `skills` field are fully preloaded into its context at launch" — [Extend Claude Code](https://code.claude.com/docs/en/features-overview)
- MCP vs skill: "MCP connects Claude to external services. Skills extend what Claude knows, including how to use those services effectively." Pattern "Skill + MCP: MCP provides the connection; a skill teaches Claude how to use it well" — [Extend Claude Code](https://code.claude.com/docs/en/features-overview)
- Hook vs skill: "Determinism — Hook: Always fires on its event; the trigger is guaranteed. Skill: Claude interprets the instructions; outcome can vary." "**Put guardrails in hooks.** An instruction like 'never edit `.env`' in CLAUDE.md or a skill is a request, not a guarantee. A `PreToolUse` hook that blocks the edit is enforcement. If a rule must hold every time, make it a hook rather than a prompt instruction." — [Extend Claude Code](https://code.claude.com/docs/en/features-overview)
- Layering: "Skills and subagents override by name ... (managed > user > project for skills ...). Plugin skills are namespaced to avoid conflicts." "Hooks merge: all registered hooks fire" — [Extend Claude Code](https://code.claude.com/docs/en/features-overview)
- Skill in a plugin: `skills/<name>/SKILL.md` under the plugin root; `${CLAUDE_PLUGIN_ROOT}` = plugin install dir, `${CLAUDE_PLUGIN_DATA}` = persistent data dir surviving updates; `${CLAUDE_SKILL_DIR}` = the skill's own directory — [Extend Claude with skills](https://code.claude.com/docs/en/skills), [Plugin manifest reference](https://code.claude.com/docs/en/plugins/manifest-reference)
- Dynamic context: `` !`command` `` runs before Claude sees the skill (2-minute timeout, non-zero exit aborts unless `|| true`); settings `disableSkillShellExecution: true` replaces it with a placeholder — [Extend Claude with skills](https://code.claude.com/docs/en/skills)
- Bundled skills: "Claude Code includes a set of bundled skills, such as `/doctor`, `/code-review`, `/batch`, `/debug`, `/loop`, and `/claude-api`. Bundled skills are prompt-based" — [Extend Claude with skills](https://code.claude.com/docs/en/skills)

### Inferences
- The 1,536-char listing cap is larger than the spec's 1,024-char description limit only because `when_to_use` is added; a spec-compliant description (≤1024) plus a `when_to_use` of ≤512 chars fits without truncation. Anything beyond is silently cut, so the trigger keywords must be in the first sentence.
- Because the listing budget is 1% of context and descriptions are dropped least-used-first, a plugin shipping many long descriptions competes with the user's other skills; short, front-loaded descriptions are a cooperation obligation, not just a triggering tactic.

### Gaps
- The current docs do not give a hard deprecation date for `.claude/commands/` or `commands/` in plugins — only "older format ... supersede them for new work".

## Q3. Anthropic's skill-authoring best practices (platform docs, agentskills.io best-practices, Oct-2025 engineering post)

### Takeaway
The rules are stable across all three Anthropic sources: descriptions in third person (platform docs) / imperative "Use this skill when..." (agentskills.io), including both what and when, with specific trigger keywords and a "pushy" list of contexts; SKILL.md body under 500 lines / <5k tokens; only add what Claude lacks; calibrate degrees of freedom to fragility; prefer scripts for deterministic work; feedback/validation loops; one-level-deep references with a TOC for >100-line files; build evals before prose; iterate by watching Claude use the skill.

### Cited Findings
- Engineering post (2025-10-16): a skill is a directory "of instructions, scripts, and resources that give agents additional capabilities"; "At startup, the agent pre-loads the `name` and `description` of every installed skill into its system prompt"; "If Claude thinks the skill is relevant to the current task, it will load the skill by reading its full `SKILL.md` into context"; code rationale: "sorting a list via token generation is far more expensive than simply running a sorting algorithm"; "Iterate with Claude: As you work on a task with Claude, ask Claude to capture its successful approaches and common mistakes into reusable context and code within a skill"; "Monitor how Claude uses your skill in real scenarios and iterate based on observations" — [Equipping agents for the real world with Agent Skills](https://www.anthropic.com/engineering/equipping-agents-for-the-real-world-with-agent-skills)
- "Concise is key ... The context window is a public good." "Default assumption: Claude is already very smart. Only add context Claude doesn't already have." Challenge each piece: "Does this paragraph justify its token cost?" — [Skill authoring best practices](https://platform.claude.com/docs/en/agents-and-tools/agent-skills/best-practices)
- Degrees of freedom: High (text instructions) "when multiple approaches are valid"; Medium (pseudocode/scripts with parameters) "when a preferred pattern exists"; Low ("Run exactly this script ... Do not modify the command or add additional flags") "when operations are fragile and error-prone / consistency is critical / a specific sequence must be followed". Analogy: "Narrow bridge with cliffs on both sides ... Open field with no hazards" — [Skill authoring best practices](https://platform.claude.com/docs/en/agents-and-tools/agent-skills/best-practices)
- Naming: "Consider using gerund form (verb + -ing)" e.g. `processing-pdfs`; acceptable alternatives: noun phrases `pdf-processing`, action `process-pdfs`; avoid `helper`, `utils`, `tools`, `documents`, `data`, `files`, and reserved words `anthropic-helper`, `claude-tools`; "Inconsistent patterns within your skill collection" — [Skill authoring best practices](https://platform.claude.com/docs/en/agents-and-tools/agent-skills/best-practices)
- Description POV: "**Always write in third person**. The description is injected into the system prompt, and inconsistent point-of-view can cause discovery problems. Good: 'Processes Excel files and generates reports'. Avoid: 'I can help you...' / 'You can use this to...'" "Claude uses it to choose the right Skill from potentially 100+ available Skills." Good example: "Extract text and tables from PDF files, fill forms, merge documents. Use when working with PDF files or when the user mentions PDFs, forms, or document extraction." — [Skill authoring best practices](https://platform.claude.com/docs/en/agents-and-tools/agent-skills/best-practices)
- agentskills.io on descriptions: "**Use imperative phrasing.** Frame the description as an instruction to the agent: 'Use this skill when...' rather than 'This skill does...'"; "**Focus on user intent, not implementation**"; "**Err on the side of being pushy.** Explicitly list contexts where the skill applies, including cases where the user doesn't name the domain directly: 'even if they don't explicitly mention "CSV" or "analysis."'"; "**Keep it concise.** A few sentences to a short paragraph" — [Optimizing skill descriptions](https://agentskills.io/skill-creation/optimizing-descriptions)
- Triggering nuance: "agents typically only consult skills for tasks that require knowledge or capabilities beyond what they can handle alone. A simple, one-step request like 'read this PDF' may not trigger a PDF skill even if the description matches perfectly" — [Optimizing skill descriptions](https://agentskills.io/skill-creation/optimizing-descriptions)
- Body length: "Keep SKILL.md body under 500 lines for optimal performance. Split content into separate files when approaching this limit." — [Skill authoring best practices](https://platform.claude.com/docs/en/agents-and-tools/agent-skills/best-practices); same in Claude Code docs: "Keep `SKILL.md` under 500 lines. Move detailed reference material to separate files." — [Extend Claude with skills](https://code.claude.com/docs/en/skills); agentskills.io: "under 500 lines and 5,000 tokens" — [Best practices for skill creators](https://agentskills.io/skill-creation/best-practices)
- Three progressive-disclosure patterns: (1) high-level guide with references (`FORMS.md`, `REFERENCE.md`, `EXAMPLES.md`), (2) domain-specific organization (`reference/finance.md`, `reference/sales.md` ... plus `grep -i` hints), (3) conditional details ("**For tracked changes**: See REDLINING.md") — [Skill authoring best practices](https://platform.claude.com/docs/en/agents-and-tools/agent-skills/best-practices)
- Nesting: "Claude may partially read files when they're referenced from other referenced files ... might use commands like `head -100` ... **Keep references one level deep from SKILL.md**"; "For reference files longer than 100 lines, include a table of contents at the top" — [Skill authoring best practices](https://platform.claude.com/docs/en/agents-and-tools/agent-skills/best-practices)
- Tell the agent *when* to load: "'Read `references/api-errors.md` if the API returns a non-200 status code' is more useful than a generic 'see references/ for details.'" — [Best practices for skill creators](https://agentskills.io/skill-creation/best-practices)
- Workflows and checklists: "For particularly complex workflows, provide a checklist that Claude can copy into its response and check off"; feedback loop "Run validator → fix errors → repeat ... This pattern greatly improves output quality"; plan-validate-execute for "Batch operations, destructive changes, complex validation rules, high-stakes operations"; "Make validation scripts verbose with specific error messages such as 'Field 'signature_date' not found. Available fields: ...'" — [Skill authoring best practices](https://platform.claude.com/docs/en/agents-and-tools/agent-skills/best-practices)
- Content rules: "Avoid time-sensitive information" (put legacy in an "Old patterns" `<details>` section); "Use consistent terminology"; "Avoid offering too many options ... Provide a default (with escape hatch)"; "Avoid Windows-style paths" — [Skill authoring best practices](https://platform.claude.com/docs/en/agents-and-tools/agent-skills/best-practices); "Provide defaults, not menus"; "Favor procedures over declarations" (teach *how to approach* a class of problems); "Aim for moderate detail — Overly comprehensive skills can hurt more than they help" — [Best practices for skill creators](https://agentskills.io/skill-creation/best-practices)
- Gotchas sections: "The highest-value content in many skills is a list of gotchas — environment-specific facts that defy reasonable assumptions ... Keep gotchas in `SKILL.md` where the agent reads them before encountering the situation." "When an agent makes a mistake you have to correct, add the correction to the gotchas section." — [Best practices for skill creators](https://agentskills.io/skill-creation/best-practices)
- Scripts: "Solve, don't defer" (handle errors in the script rather than "let Claude figure it out"); avoid "voodoo constants" (Ousterhout's law) — document every magic number; utility scripts are "More reliable than generated code; Save tokens; Save time; Ensure consistency"; "Make execution intent clear: 'Run `analyze_form.py`' (execute) vs 'See `analyze_form.py`' (read)"; "Prefer scripts for deterministic operations: Write `validate_form.py` rather than asking Claude to generate validation code"; "Bundle comprehensive resources ... no context penalty until accessed" — [Skill authoring best practices](https://platform.claude.com/docs/en/agents-and-tools/agent-skills/best-practices)
- Signal to bundle a script: "If you notice the agent independently reinventing the same logic each run ... that's a signal to write a tested script once and bundle it in `scripts/`." — [Best practices for skill creators](https://agentskills.io/skill-creation/best-practices)
- MCP tool refs inside skills: "always use fully qualified tool names ... Format: `ServerName:tool_name`" — [Skill authoring best practices](https://platform.claude.com/docs/en/agents-and-tools/agent-skills/best-practices)
- "Test with all models you plan to use" (Haiku: enough guidance? Sonnet: clear and efficient? Opus: avoids over-explaining?) — [Skill authoring best practices](https://platform.claude.com/docs/en/agents-and-tools/agent-skills/best-practices)
- Iterating: the "Claude A / Claude B" method (Claude A helps author; Claude B, a fresh instance, is observed using the skill); "Claude models understand the Skill format and structure natively. You don't need special system prompts or a 'writing skills' skill"; watch for "Unexpected exploration paths / Missed connections / Overreliance on certain sections / Ignored content" — [Skill authoring best practices](https://platform.claude.com/docs/en/agents-and-tools/agent-skills/best-practices)
- Ground in expertise: "asking an LLM to generate a skill without providing domain-specific context ... The result is vague, generic procedures ('handle errors appropriately')"; extract from a hands-on task or synthesize from runbooks, review comments, version-control history, failure cases; "Read agent execution traces, not just final outputs" — [Best practices for skill creators](https://agentskills.io/skill-creation/best-practices)
- Explain why over ALWAYS/NEVER: skill-creator instructs "if finding yourself writing ALWAYS/NEVER, reframe to explain reasoning" — [skill-creator SKILL.md](https://github.com/anthropics/skills/blob/main/skills/skill-creator/SKILL.md); agentskills.io: "Reasoning-based instructions ('Do X because Y tends to cause Z') work better than rigid directives ('ALWAYS do X, NEVER do Y')" — [Evaluating skill output quality](https://agentskills.io/skill-creation/evaluating-skills)

## Q5. CLAUDE.md, `.claude/rules/`, imports, hierarchy, "programs beat prose", and auto memory

### Takeaway

- Scanning: Claude Enterprise orgs can enable "Skill and plugin security scanning" for claude.ai/Cowork uploads (blocks failed or unfinished scans); "Scanning doesn't cover the Claude API. Skills you upload through the Skills API (`/v1/skills`), including from the Claude Console, aren't scanned, so for API deployments, rely on the review checklist and version pinning." — [Skills for enterprise](https://platform.claude.com/docs/en/agents-and-tools/agent-skills/enterprise)
- Versioning strategy: "Production: Pin Skills to specific versions. If you omit `version`, requests use the latest version, so a new version uploaded by anyone in the workspace immediately changes what production agents run." "Integrity verification: Compute checksums of reviewed Skills and verify them at deployment time. Use signed commits in your Skill repository." "Custom Skills do not sync across surfaces. Skills uploaded to the API are not available on claude.ai or in Claude Code, and vice versa." — [Skills for enterprise](https://platform.claude.com/docs/en/agents-and-tools/agent-skills/enterprise)
- Skills API mechanics: endpoints `GET/POST /v1/skills`, `GET/DELETE /v1/skills/{id}`, `POST /v1/skills/{id}/versions`, `GET /v1/skills/{id}/versions/list`; attached via `container.skills[]` with `type: anthropic|custom`, `skill_id`, `version`; requires the code-execution tool (`code_execution_20250825`); "Up to 20 Skills per request"; upload "Under 30 MB (uncompressed)"; Anthropic skills `pptx`, `docx`, `xlsx`, `pdf` with date versions (e.g. `20251013`); "A new version is a complete snapshot, not a delta"; "Any API key with access to a workspace can read, invoke, and delete every custom Skill uploaded to that workspace" — [Using Skills with the API](https://platform.claude.com/docs/en/build-with-claude/skills-guide); "Skills on the API run in a sandboxed container with no network access and no runtime package installation" — [Agent Skills overview](https://platform.claude.com/docs/en/agents-and-tools/agent-skills/overview)
- Claude Code plugin trust: "A Claude Code plugin you install can execute arbitrary code on your machine with your user privileges." Hooks "run as shell commands"; stdio MCP servers and LSP servers run as local processes; each enabled plugin's `bin/` is added to the Bash tool's `PATH`; "Skills, commands, and agents: these enter Claude's context as instructions"; "Claude Code runs hooks and MCP servers outside the sandbox"; auto-update means "the files you reviewed can change on disk" — [Plugin security and trust](https://code.claude.com/docs/en/plugins/security)
- Marketplace tiers: official names (`claude-plugins-official`, `agent-skills`, `anthropic-agent-skills`, ...) and community names (`claude-community`, ...) are accepted "only for marketplaces sourced from `github.com/anthropics/` repositories, so a third-party marketplace can't present itself as an Anthropic one"; `claude-community` pins entries to commit SHAs; `archive` sources can pin `sha256`. Review steps: `claude plugin marketplace list`, `/plugin` details pane "Will install", read `hooks/hooks.json`, `.mcp.json`, `bin/`, and `claude --plugin-dir <dir> plugin details <name>` for a "Component inventory". Trust warning text: "Anthropic does not control what MCP servers, files, or other software are included in plugins and cannot verify that they will work as intended or that they won't change." — [Plugin security and trust](https://code.claude.com/docs/en/plugins/security)
- Org controls: allowlist/blocklist marketplace sources, force-enable plugins, disable `--plugin-dir`/`--plugin-url`/`CLAUDE_CODE_PLUGIN_DIRS`, limit hooks to managed/force-enabled plugins, `syncClaudeAiPlugins`; telemetry reports non-official plugins as `third-party` unless `OTEL_LOG_TOOL_DETAILS=1` — [Plugin security and trust](https://code.claude.com/docs/en/plugins/security)
- Distribution channels for Anthropic's own skills: `/plugin marketplace add anthropics/skills` then `/plugin install document-skills@anthropic-agent-skills` / `example-skills@anthropic-agent-skills`; claude.ai upload; Skills API — [anthropics/skills](https://github.com/anthropics/skills)
- Synced skills content restrictions (v2.1.228+): in non-cloud sessions, `!` commands, `@` file references and `${CLAUDE_*}` placeholders in claude.ai-synced skills are not executed/expanded — [Extend Claude with skills](https://code.claude.com/docs/en/skills)

### Inferences
- A plugin author is on the other side of this trust model: everything reviewers are told to look for (network calls, `!` shell injection, hooks, `bin/`, credentials, "ignore safety rules" directives) should be absent or explicitly documented in the plugin's README so a `claude plugin details` inventory matches the stated purpose.

### Gaps
- Exact list of "signs of malicious behavior" the claude.ai scanner checks is only summarized in the enterprise page (hidden code execution, sending data to an outside service, tampering with safeguards); the linked Help Center article was not fetched.

## Implications for a Claude Code plugin repo (create-cmp, 11 shipped skills)

### Takeaway
Ship spec-portable frontmatter, front-load short pushy descriptions, keep bodies under 500 lines with one-level references, put deterministic work in scripts and guardrails in hooks, and measure every skill with `claude plugin eval` (CI) plus skill-creator trigger evals (authoring) — while auditing the plugin against the same checklist reviewers are told to apply.

### Cited Findings (each rule with its source)
- DO keep every shipped SKILL.md's `name` ≤64 chars, lowercase/digits/hyphens, no `--`, equal to its directory name; `description` ≤1024 chars, non-empty, no XML tags, no "anthropic"/"claude" in `name` — [Spec](https://agentskills.io/specification), [Platform best practices](https://platform.claude.com/docs/en/agents-and-tools/agent-skills/best-practices). Validate with `skills-ref validate` and `claude plugin validate` (which now checks "SKILL.md files whose frontmatter fails to parse") — [Spec](https://agentskills.io/specification), [CHANGELOG](https://github.com/anthropics/claude-code/blob/main/CHANGELOG.md)
- DO put the key use case in the first sentence of `description`: the listing truncates `description`+`when_to_use` at 1,536 chars and drops whole descriptions (least-used first) when the 1%-of-context budget overflows — [Claude Code skills](https://code.claude.com/docs/en/skills). DON'T rely on `when_to_use` for portability — it is a Claude Code-only field — [Claude Code skills](https://code.claude.com/docs/en/skills)
- DO write descriptions in third person / imperative "Use when...", naming what the skill does and the user-intent triggers (including cases where the user doesn't name the domain); DON'T write "I can help you..." — [Platform best practices](https://platform.claude.com/docs/en/agents-and-tools/agent-skills/best-practices), [Optimizing descriptions](https://agentskills.io/skill-creation/optimizing-descriptions)
- DO state what the skill does NOT cover when near-miss prompts false-trigger (e.g. cmp-new's "do NOT redirect" guardrails), because "Add specificity about what the skill does *not* do" is the prescribed fix for over-broad descriptions — [Optimizing descriptions](https://agentskills.io/skill-creation/optimizing-descriptions)
- DO keep SKILL.md under 500 lines / ~5k tokens; move detail to `references/` linked one level deep with a TOC for files >100 lines, and say *when* to read each reference — [Spec](https://agentskills.io/specification), [Platform best practices](https://platform.claude.com/docs/en/agents-and-tools/agent-skills/best-practices), [agentskills.io best practices](https://agentskills.io/skill-creation/best-practices)
- DO prefer bundled scripts (`scripts/`, invoked via `${CLAUDE_SKILL_DIR}` or `${CLAUDE_PLUGIN_ROOT}`) for deterministic steps, with explicit error handling, documented constants, and verbose validation messages; make "run" vs "read" intent explicit — [Platform best practices](https://platform.claude.com/docs/en/agents-and-tools/agent-skills/best-practices), [Claude Code skills](https://code.claude.com/docs/en/skills)
- DO put "must always" rules in hooks or permission rules, not in CLAUDE.md or SKILL.md prose ("a request, not a guarantee") — [Extend Claude Code](https://code.claude.com/docs/en/features-overview), [Best practices](https://code.claude.com/docs/en/best-practices), [Steering blog](https://claude.com/blog/steering-claude-code-skills-hooks-rules-subagents-and-more)
- DO set `disable-model-invocation: true` on side-effectful skills (publish, release, refresh) — "Use `disable-model-invocation: true` for skills with side effects. This saves context and ensures only you trigger them." — [Extend Claude Code](https://code.claude.com/docs/en/features-overview); note it also blocks preload into subagents and scheduled-task firing — [Claude Code skills](https://code.claude.com/docs/en/skills)
- DO use `user-invocable: false` for background-knowledge skills that should never appear in the `/` menu — [Claude Code skills](https://code.claude.com/docs/en/skills)
- DO write new plugin entries as `skills/<name>/SKILL.md`, not `commands/*.md` ("Commands are the older format, and skills supersede them for new work") — [Plugin components](https://code.claude.com/docs/en/plugins/components)
- DO reference MCP tools by fully qualified `Server:tool` names inside skills — [Platform best practices](https://platform.claude.com/docs/en/agents-and-tools/agent-skills/best-practices)
- DON'T embed time-sensitive statements or pinned versions in prose; use a "current method / old patterns" structure — [Platform best practices](https://platform.claude.com/docs/en/agents-and-tools/agent-skills/best-practices) (consistent with create-cmp's ground-truth-deriver rule)
- DON'T present menus of tools; pick a default with an escape hatch — [Platform best practices](https://platform.claude.com/docs/en/agents-and-tools/agent-skills/best-practices), [agentskills.io best practices](https://agentskills.io/skill-creation/best-practices)
- DO keep a gotchas section in SKILL.md and append each correction Karel makes to it — [agentskills.io best practices](https://agentskills.io/skill-creation/best-practices)
- DO watch the recall ceiling: 11 skills each add a listing line every turn; "limit the number of Skills loaded simultaneously ... stop adding when performance degrades"; consolidate only when evals confirm equivalence — [Skills for enterprise](https://platform.claude.com/docs/en/agents-and-tools/agent-skills/enterprise); use `/skill-doctor` (v2.1.261) to see per-skill cost and use counts — [Claude Code skills](https://code.claude.com/docs/en/skills), [CHANGELOG](https://github.com/anthropics/claude-code/blob/main/CHANGELOG.md)
- DO add a `claude plugin eval` suite under `evals/` (or a `plugin.json`-recorded dir if `evals/` is taken by skill-creator files): one case per skill with a natural-phrasing prompt, a `tool_used: Skill` grader plus one result grader (regex over a produced file preferred over `llm`), default 3 runs, `--threshold` gate in CI; keep skill-creator's `evals/evals.json` separate since "neither tool reads the other's case files" — [Test plugins with evals](https://code.claude.com/docs/en/plugin-evals)
- DO run trigger evals per skill: ~20 labelled queries (8-10 should / 8-10 should-not, near-misses), 3 runs each, 0.5 trigger-rate threshold, 60/40 train/validation, ≤5 iterations, then 5-10 fresh queries — [Optimizing descriptions](https://agentskills.io/skill-creation/optimizing-descriptions); skill-creator automates this loop — [skill-creator SKILL.md](https://github.com/anthropics/skills/blob/main/skills/skill-creator/SKILL.md)
- DO test coexistence: a new skill's description must not "steal triggers from existing Skills" — run the should-not-trigger sets of sibling skills after adding one — [Skills for enterprise](https://platform.claude.com/docs/en/agents-and-tools/agent-skills/enterprise)
- DO make the plugin reviewable: keep `hooks/hooks.json`, `.mcp.json`, and any `bin/` minimal and documented; expect users to run `claude --plugin-dir . plugin details create-cmp`; never hardcode credentials; avoid unexplained `!` shell injection and external URL fetches in SKILL.md — [Plugin security and trust](https://code.claude.com/docs/en/plugins/security), [Skills for enterprise](https://platform.claude.com/docs/en/agents-and-tools/agent-skills/enterprise)
- DO keep the repo CLAUDE.md under 200 lines, owner-reviewed like code, holding only what Claude cannot derive; move on-demand material to skills and path-scoped `.claude/rules/*.md`; run `/doctor` for trim proposals — [memory](https://code.claude.com/docs/en/memory), [Best practices](https://code.claude.com/docs/en/best-practices), [Steering blog](https://claude.com/blog/steering-claude-code-skills-hooks-rules-subagents-and-more)
- DO keep MEMORY.md as a one-line-per-entry index under 200 lines / 25 KB with detail in topic files — the load limit is a hard truncation — [memory](https://code.claude.com/docs/en/memory)
- DON'T pin the plugin's distribution to a single surface assumption: Claude Code plugin skills accept all fields, but the same SKILL.md uploaded to claude.ai or `/v1/skills` fails on any non-spec field (`Unexpected key(s) in SKILL.md frontmatter`) — [Claude Code skills](https://code.claude.com/docs/en/skills)

### Inferences
- create-cmp's existing stances ("rules that are programs", ground-truth deriver, log corrections, index-style MEMORY.md) are directly endorsed by Anthropic's 2026 docs. The one house rule without an Anthropic counterpart is "no checklists/convert-or-cut": Anthropic explicitly recommends copyable checklists for multi-step skill workflows, so that rule should be scoped to *presentation* (no checklist slop in outputs), not to SKILL.md workflow structure.
- The gap most worth closing for an 11-skill plugin is measurement: Anthropic now provides a CI-grade instrument (`claude plugin eval`, Sept 2026) whose most common first finding is exactly "Δ≈0 with `tool_used: Skill` failing" — i.e., a description problem.

### Gaps
- No Anthropic guidance was found on an upper bound of skills per plugin, only the API's 20-per-request cap and the qualitative recall warning.
- Whether `claude plugin eval` can drive a device/emulator lane (Bash granted, sandboxed, no network by default) is untested; the docs say Bash runs under the OS sandbox with network limited to `--allow-tools "WebFetch(domain:...)"` grants, which likely excludes adb/Gradle network access.
