**Method, stated so it can be attacked.**

- A doc is **stale** only where a *present-tense* sentence is refuted by a tree fact I can
  cite (a grep, a `--help` line, a ground-truth field, an absent file). A doc that narrates a
  past tree under a banner saying so is **current** — `test/doc-counts.test.mjs:34-40` makes
  exactly this distinction and I follow it: *"A count that records a past tree is not drift,
  and a scanner that cannot tell the difference deletes honest prose."*
- Depth is tiered, per the lead's instruction: full read of the load-bearing docs; ADRs read
  as header + Status + decision sentence + one grep of the decision's key noun; proposals as

### 1.4 Two premise corrections (findings)

**F-0 — `create-cmp harness fleet` does not exist.** The brief listed it as a subcommand to
spec. `bin/create-cmp.mjs:22` declares
`COMMANDS = new Set(["create","doctor","upgrade","clean","verify","harden","attach","harness","help"])`
and the `harness` case (`bin/create-cmp.mjs:174-199`) knows `init`, `relock`, `upgrade` only —
an unknown sub prints `create-cmp harness: unknown subcommand …`. `node bin/create-cmp.mjs
harness fleet --help` prints the top-level help and exits 0. The fleet surface that exists is
**`create-cmp harness upgrade --fleet <manifest>`** (`bin/create-cmp.mjs:190-194`, delegating to
`packages/harness/install/fleet.mjs`), its twin `prooflane upgrade --fleet <manifest>`, and the
repo-internal `scripts/fleet-check.mjs` (a different thing: the device-tier runner). §3 specs
those instead.

**F-1 — the deriver's CLI-command count disagrees with the dispatcher.**
`ground-truth.mjs --json` reports `cliCommands.count: 7`
(`attach, clean, create, doctor, harden, upgrade, verify`); the dispatcher knows 9
(`bin/create-cmp.mjs:22`), the extra two being `harness` and `help`. `--help` documents
`harness init` and `harness relock` as commands. Consequence: the count gate
(`test/doc-counts.test.mjs:207` `key: "CLI commands"`) will **fail any public surface that
honestly says "9 commands"** and pass one that omits the whole `harness` verb. This is a gate
disagreeing with the tool, not a doc bug — I am not proposing a change to the gate, only
flagging that the version of truth the docs are held to excludes a shipped command family.
Root cause, read from source: `scripts/ground-truth.mjs:137` — *"CLI commands — one module per
command in src/commands/"* — and `harness` is implemented in `packages/harness/install/`, so the
deriver cannot see it by construction.

**F-2 — `--help` is hand-written and omits shipped surface.** `printHelp()`
(`bin/create-cmp.mjs:213-245`) is a string literal, not derived from the dispatcher or from
`KNOWN_FLAGS` (`src/lib/args.mjs:50-65`). Omitted today: `harness upgrade` and
`harness upgrade --fleet <manifest>` (dispatched at `:190-197`, listed only in the
unknown-subcommand usage at `:201-203`); `--new-profile` at this door (known at
`src/lib/args.mjs:61`, documented only by `prooflane --help`); `attach`'s
`--profile --specs --citation-roots --receipt` (known at `:54`, advertised by `attach` itself at
`src/commands/attach.mjs:259-261`, absent from `attach flags:`); `create`'s
`--firestore --storage --functions --fcm` (known at `:58`, documented in `docs/USAGE.md:137`).
No subcommand has its own `--help` — every `create-cmp <cmd> --help` prints the same page.
